## نتیجهٔ تصمیم

بعد از Back Office، اولویت درست برای Hero یک پنل بزرگ یا Orchestrator جدید نیست. اول باید مسیر زیر قابل مشاهده، قابل‌بازسازی و قابل‌توقف باشد:

```text
event امن و correlated
  -> timeline و projection بک‌آفیس
  -> احراز هویت قابل‌ابطال
  -> event/outbox durable
  -> pilot deterministic
  -> benchmark قابل‌تکرار
  -> تصمیم مالک برای اجرای واقعی
```

## مرزهای حفظ‌شده

- هیچ Provider واقعی، external spend، Secret change، deploy، پیام خارجی یا Production فعال نشده است.
- `pilot dry-run` فقط مسیر deterministic را می‌آزماید و readiness واقعی Provider را تأیید نمی‌کند.
- benchmark فقط advisory است و نمی‌تواند Provider، mutation یا release را authorize کند.
- Outbox worker عمداً dispatch نمی‌کند؛ فقط primitive امن claim/ack/fail را فراهم می‌کند.
- Back Office فعلاً read-only است و در محیط Production باید پشت احراز هویت و policy دسترسی قرار گیرد.
