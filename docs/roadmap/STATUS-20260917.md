### اصلاح بعدی source — رندر امن اتاق کنترل پروژه

اتاق کنترل پروژه پیش از این کارت‌های عملیاتی را فقط پس از اجرای JavaScript مرورگر می‌ساخت؛ در

ثبت انتخاب نسخه‌دار را تکمیل می‌کند. تست regression برای حالت بدون JavaScript اضافه شده است.
این اصلاح هنوز Candidate جداگانه نیست و تا ساخت و promotion نسخهٔ بعدی روی Runtime Test
فعال نشده است.

قابلیت تکمیل فرم با نام canonical «Advisor / ادوایزر» ادامه دارد؛ نام فنی و authorization capability قبلی `form-suggestions` برای سازگاری حفظ شده است. Advisor اکنون analysis تصمیم شامل assumption/risk/test/improvement و برای ورودی‌های فایل، طرح review-only سند یا تصویر ارائه می‌کند. هیچ binary، مسیر فایل، محتوای انتخاب‌شده یا upload خودکار به Provider داده نمی‌شود. مسیر canonical `/api/advisor*` است و legacy API همچنان کار می‌کند.

### به‌روزرسانی ۲۰۲۶-۰۹-۲۰ — پیشنهاد فرمِ بازخوردپذیر و سند اختیاری

در source، هر بازخورد معتبرِ ادمین برای پیشنهاد فرم، مستقیم و فقط در درخواست گذرای Provider قرار می‌گیرد. Provider موظف است یک کارت تازه با تغییر محسوسِ متناسب با بازخورد و `feedbackResponse` کوتاهی برگرداند که تفسیر بازخورد و تغییر اعمال‌شده را برای ادمین توضیح می‌دهد؛ این توضیح جای پاسخ ثابت UI را گرفته، اما زنجیرهٔ فکر داخلی نیست. اگر این توضیح ناقص باشد، پیشنهاد معتبر fail-closed رد نمی‌شود و Hero فقط یک پیام گذرای امن نشان می‌دهد.

برای فرم موجود «ورودی پروژه» که ذاتاً اختیاری است، Provider فقط در صورت مفیدبودن می‌تواند یک پیش‌نویس متن کوتاهِ قابل‌خواندن با filename امن `.txt` یا `.md` پیشنهاد کند. Owner/Admin آن را در Popup می‌خواند، با «قرار دادن سند در فرم» فقط فیلدهای فرم اصلی را پر می‌کند و سپس با ثبت جداگانهٔ همان فرم، در صورت تأیید، آن را به ورودی خصوصی همان Project upload می‌کند. هیچ ذخیره یا upload خودکار وجود ندارد. بازخورد، گفت‌وگوی AI و پیش‌نویسِ انتخاب‌نشده با بسته‌شدن Popup حذف می‌شوند و به event، audit، context ساخت‌یافته، تاریخچهٔ پروژه یا storage مرورگر نوشته نمی‌شوند.

شواهد source این تغییر: تست هدفمند domain/UI/API `24/24` و `pnpm check` کامل `483/483` PASS؛ Documentation `148` سند با صفر خطا و build `298` ماژول و `54` فایل JSON موفق‌اند. این برش هیچ فراخوانی Provider زنده، تغییر هزینه/authorization، Secret، Profile، Binding، Pilot یا Production انجام نداده است؛ promotion Test و evidence کامل CI هنوز مرحلهٔ جداگانهٔ بعدی است.

### به‌روزرسانی ۲۰۲۶-۰۹-۲۰ — اصلاح دقیقِ چندفیلدی در بازخورد پیشنهاد فرم

برای بازخوردهای صریحِ چندفیلدی، Hero دیگر فقط «کل فرم» را به AI نمی‌سپارد. عبارت‌هایی مانند «فیلد اول را کوتاه‌تر کن و فیلد دوم را مفصل‌تر کن» در همان درخواست گذرا به field واقعیِ دارای نام، برچسب و جایگاه نگاشت می‌شوند و Provider قرارداد جداگانهٔ همان fieldها را دریافت می‌کند. برای field متن، «کوتاه» حداکثر ۲۲۰ نویسه و «مفصل» دست‌کم ۲۲۰ نویسهٔ مرتبط با همان field است؛ پس از پاسخ، Hero این شرط را برای هر fieldِ هدف جداگانه می‌سنجد. اگر Provider فقط یکی را نادیده بگیرد، فقط همان مقدار با تکمیل ایمن و سازگار با دستور جایگزین می‌شود و بقیهٔ فرم دست‌نخورده می‌ماند.

`feedbackResponse` باید نام fieldهای تغییرکرده و تفسیر کوتاهِ AI را به ادمین نشان دهد؛ زنجیرهٔ فکر نمایش داده نمی‌شود. متن خام بازخورد و نگاشت field-aware فقط در حافظه و سؤال گذرای همان call هستند و به context ساخت‌یافته، event، audit، snapshot، تاریخچه یا storage مرورگر راه ندارند. تست domain/integration این مسیر در Linux container بدون شبکه `25/25` PASS شده است؛ زنجیرهٔ کامل معادل `pnpm check` با Node مرجع نیز `484/484` PASS، documentation `148/0` و build `298` ماژول / `54` JSON بود. CI نیز برای Candidate Test `1.1.5-rc.26` (workflow `35523233494`، commit `2ffebdeb2f9db6aea8ec2848d7a9a936dc74f104`، digest `sha256:9965fbce6f9ab1dcf1f11103a66dff01c1983f573cf93b9f3da8f085be72602f`) کامل موفق است؛ promotion و verify Test هنوز گیت عملیاتی جداست. هیچ Provider زنده، هزینهٔ خارجی، Secret، Profile، Binding، authorization، Pilot یا Production در این تغییر لمس نشده است.
