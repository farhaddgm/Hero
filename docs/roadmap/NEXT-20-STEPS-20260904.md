## تصمیم فنی بستهٔ فعلی

## کارهای انجام‌شده در این بسته

- `PostgresBenchmarkStore` اضافه شد و از `HERO_POSTGRES_URL` به‌صورت اختیاری ساخته می‌شود؛ نبودن این متغیر رفتار قبلی را حفظ می‌کند.
- Control Plane هنگام startup، پس از ping موفق PostgreSQL، تاریخچه را می‌خواند و projection را hydrate می‌کند.
- endpointهای owner-gated برای history و compare اضافه شدند.
- Back Office history امن را نشان می‌دهد؛ دادهٔ خام، prompt، output، credential و token نمایش داده نمی‌شود.
- audit دسترسی read model با migration، adapter، cursor و endpoint جداگانه اضافه شد؛ audit فرمان‌ها در `/api/audit` بدون تغییر باقی ماند.
- نسخه/آخرین event در Team projection اضافه شد و UI تاریخچهٔ diff، rollback اصول و provenance دانش را نشان می‌دهد.
- Admin session از Owner جدا شد؛ Admin خواندن و mutationهای صریح کاتالوگ AI و draft/rollback اصول تیم را دارد و تأیید نهایی Team همچنان owner-only است.
- planner سقف عددی هم‌زمانی تیم و تعارض resource claimهای زمان‌دار را قبل از dispatch گزارش می‌کند.
- Diagnostic اکنون snapshot ظرفیت Planner، نوع تعارض، مصرف تیم و resource claimها را بدون mutation در Back Office و endpoint تشخیص نشان می‌دهد.
- Back Office برای مسیرهای خودش فقط GET را می‌پذیرد و هر روش دیگر را با `405` و `Allow: GET` رد می‌کند.
- حافظهٔ فعلی پروژه در Back Office به‌صورت metadata و provenance امن نمایش داده می‌شود و محتوای اصلی حذف می‌ماند.
- تاریخچهٔ بازیابی Context در Project Memory به‌صورت read model محدود، قابل Snapshot/Hydration و بدون محتوای حافظه در Back Office نمایش داده می‌شود.
- تاریخچهٔ Policy نقش‌های AI در Back Office دکمهٔ rollback نسخه‌دار دارد؛ rollback همیشه یک نسخهٔ تازه می‌سازد و تاریخچه را حذف نمی‌کند.
- مدارشکن bounded Provider با threshold، reset timeout، probe نیمه‌باز و رویدادهای بازشدن/بسته‌شدن اضافه شد؛
- Planner پیش از تصمیم خروجی readiness جاری تیم‌ها را refresh می‌کند و ابهام پلتفرم/تعارض ظرفیت را به escalation امن تبدیل می‌کند؛
- findingهای Performance/Evaluation به اقدام آموزشی advisory با owner review و evidence requirement متصل شدند؛
- تشخیص integrity projection، freshness snapshot و rebuild کل read model از Snapshot+Event به مسیر تشخیصی اضافه شد.
- تست‌های idempotency، conflict، duplicate case، restore، compare، hydration، HTTP auth و UI اضافه شدند.

کد و replay محلی گام ۱۲ انجام شده است. مرحلهٔ بعد اجرای همین شواهد روی Test مستقل است؛ گام‌های ۱۸ تا ۲۰ فقط بعد از فراهم‌شدن ورودی/زیرساخت/مجوز لازم اجرا می‌شوند؛ اجرای آن‌ها با حدس‌زدن Secret یا تغییر Caddy و سرویس‌های دیگر ممنوع است.
