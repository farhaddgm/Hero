# وضعیت جاری Hero — ۲۰۲۶-۰۹-۱۰

این سند مرجع فعلی وضعیت است. اسناد دارای تاریخ قدیمی‌تر، سابقهٔ همان روز را نگه می‌دارند و هر تعارضی باید به نفع این سند تفسیر شود.

## خلاصهٔ اجرایی

- محیط مستقل Test با Compose project برابر `hero-test` فعال است؛ Control Plane، PostgreSQL و proxy احراز هویت همگی healthy هستند.
- پورت برنامه فقط روی `127.0.0.1:43101` bind شده و PostgreSQL پورت عمومی ندارد.
- دامنهٔ رسمی Test برابر `test.hero.beeproject.ir` است؛ TLS فعال، `/health=200`، `/ready=200` و Back Office بدون احراز هویت `401` است.
- persistence واقعی Test برابر `postgresql` و readiness برابر `ready` است.
- startup hydration از snapshotهای نسخه‌دار PostgreSQL موفق است: ۱۱ registry، بدون registry گمشده، و integrity رویداد/snapshot معتبر.
- restart کنترل‌شدهٔ فقط Control Plane انجام شد و digest projection و وضعیت hydration بدون تغییر باقی ماند.
- فایل قدیمی `compose.test.yaml` فعال نبود؛ بدون حذف، در مسیر ignored و بازیافت‌پذیر `var/quarantine/compose.test.yaml.legacy-20260904.disabled` کنار گذاشته شد. اجرای Test فقط با `compose.yaml` و project name برابر `hero-test` مجاز است.
- Production سالم و احراز‌شده است؛ همان image immutable با digest فعلی Test را اجرا می‌کند، `/health=200`، `/ready=200` با `persistence=postgresql` دارد و ورود Back Office دامنهٔ `hero.beeproject.ir` موفق شده است.
- قرارداد source/config بین Test و Production همسان‌سازی و versioned شد؛ `pnpm check:environment-parity` مجموعهٔ env نمونه، defaultهای ایمن، Compose و قفل‌های Provider/هزینه را کنترل می‌کند. این هنوز جایگزین برابری runtime یا promotion واقعی نیست.
- مسیر Artifact immutable تکمیل شد: Release Candidate image را با tag commit در GHCR منتشر می‌کند؛ Test و Production همان digest کامل را با `--no-build` اجرا می‌کنند و تفاوت پورت، دامنه، Secret، شبکه و دیتابیس آن‌ها عمدی و محیطی است.

## تصمیم مالک — ۲۰۲۶-۰۹-۱۰

تهیهٔ سرور/VM دوم و اجرای Recovery فعلاً به تعویق افتاد. توسعه، verification و تست‌های محیط Test روی همین سرور ادامه پیدا می‌کند؛ Recovery واقعی Clean Linux همچنان پیش‌شرط استفادهٔ عملیاتی نهایی و هرگونه promotion به Production است.

## گیت‌های باز

1. Recovery روی Clean Linux مستقل فعلاً با تصمیم مالک deferred است؛ برای توسعه و Test فعلی لازم نیست، اما قبل از استفادهٔ عملیاتی نهایی و Production باید انجام و ثبت شود.
2. Adapterهای Provider واقعی موجودند، ولی credential، سقف هزینه و مجوز مستقل external-spend هنوز فعال نشده‌اند.
3. درخواست پایلوت VPN و معیار پذیرش پیشنهادی باید توسط مالک تصویب شود؛ runtime VPN به AI Provider نیاز ندارد، اما توسعهٔ زنده با Provider AI همچنان مجوز جدا می‌خواهد.
4. Production فقط پس از موفقیت recovery، پایلوت، review و مجوز مستقل `production-deploy` قابل promotion است.

## Pricing Catalog — اجرای synthetic تکمیل‌شده

Pricing Catalog نسخه‌دار برای همهٔ Provider/Modelها در
[FUTURE-REQUIRED-PRICING-CATALOG.md](FUTURE-REQUIRED-PRICING-CATALOG.md) ثبت و طبق
تأیید مالک در حالت synthetic پیاده‌سازی شد: قرارداد versioned، Registry، migration 007،
Adapterهای token/request-unit، fail-closed پیش از dispatch و تست‌های بدون شبکه.
نرخ‌های دستی runtime دیگر منبع هزینه نیستند و استفادهٔ صریح از آن‌ها رد می‌شود.
همگام‌سازی رسمی Catalog، اجرای migration روی محیط واقعی Test و Provider واقعی هنوز
عمداً خاموش و جداگانه gated هستند.
