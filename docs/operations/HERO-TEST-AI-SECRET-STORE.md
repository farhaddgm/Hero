# ثبت امن کلیدهای AI در Hero Test

این سند راهنمای سادهٔ Owner برای وصل‌کردن Providerهای AI به محیط Test است. این مسیر برای زمانی است که به Secret Manager بیرونی دسترسی ندارید.

## نکتهٔ امنیتی مهم

کلید API را در چت، ایمیل، Issue، فایل Git یا پیام برای هیچ‌کس نفرستید. کلید را فقط در فرم «اتصال‌های AI» روی دامنهٔ Test و از طریق HTTPS وارد کنید. Hero مقدار خام را یک‌بار دریافت می‌کند، با AES-256-GCM روی volume خصوصی Test رمزنگاری می‌کند و بعد فقط مرجع و وضعیت را نشان می‌دهد. مقدار کلید در پاسخ API، Event، PostgreSQL، گزارش، لاگ و رابط کاربری برگردانده نمی‌شود.

این Secret Store داخلی فقط Test است و برای Production طراحی نشده. Production باید به Secret Manager سازمانی/KMS متصل شود.

## پیش‌نیاز یک‌بارهٔ اپراتور

اگر وضعیت صفحه می‌گوید «Secret Store فعال نیست»، سرویس Test هنوز با این تنظیمات راه‌اندازی نشده است. اپراتور باید فقط در فایل تنظیمات Test (نه Production) این مقادیر غیرمحرمانه را قرار دهد و Control Plane Test را recreate/restart کند:

در تنظیمات Test سه مقدار زیر را قرار دهید:

| نام تنظیم | مقدار در Test |
|---|---|
| `HERO_SECRET_STORE_ENABLED` | `true` |
| `HERO_SECRET_STORE_DIR` | `/var/lib/hero/secret-store` |
| `HERO_SECRET_STORE_MASTER_KEY` | خالی بماند تا Hero آن را خودکار بسازد |

با خالی‌بودن `HERO_SECRET_STORE_MASTER_KEY`، Hero یک کلید ۳۲‌بایتی تصادفی را داخل همان volume با مجوز فایل `0600` می‌سازد. آن volume و فایل master key را حذف نکنید؛ حذف آن‌ها باعث می‌شود رکوردهای قبلی قابل رمزگشایی نباشند. مقدار master key را در Git یا چت قرار ندهید.

پس از راه‌اندازی، باید `GET /ready` مقدار آماده‌بودن Test را بدهد و در صفحهٔ اتصال‌های AI حالت «Secret Store فعال» دیده شود.

## ثبت کلید، گام‌به‌گام

۱. در مرورگر این مسیر canonical را باز کنید: `https://test.hero.beeproject.ir/api/portal?surface=identity`. با **ورود انسانی Owner** وارد شوید: ایمیل، رمز حساب انسانی و سپس کد MFA. Basic Auth شبکه فقط در صورت نمایش پنجرهٔ شبکه‌ای استفاده می‌شود؛ آن با حساب انسانی فرق دارد. مسیرهای قدیمی `/backoffice` و `/portfolio` برای این کار استفاده نشوند.

۲. از نوار کناری «اتصال‌های AI» را انتخاب کنید. باید صفحهٔ `اتصال‌های AI، نسخه‌ها و تخصیص‌ها` باز شود. در بالای همین صفحه دکمهٔ `رفتن به ثبت امن کلید` را بزنید؛ این دکمه شما را مستقیم به فرم `ثبت امن کلید Provider` می‌برد. اگر صفحه دوباره Login خواست، همان دامنه و همان پنجرهٔ مرورگر را نگه دارید؛ نشست انسانی شش ساعت اعتبار دارد و بین تب‌ها مشترک است.

۳. در بخش «ثبت امن کلید Provider» از فهرست Provider یکی را انتخاب کنید:

   - OpenAI / ChatGPT
   - Anthropic / Claude
   - Google / Gemini
   - Cursor Cloud Agent
   - OpenAI-compatible

۴. کلید API را در فیلد «کلید API» Paste کنید. کلید را در هیچ فیلد دیگری وارد نکنید. اگر Hero کد MFA خواست، کد شش‌رقمی جاری Authenticator را در فیلد MFA وارد کنید.

۵. «ذخیرهٔ امن کلید» را بزنید. در موفقیت، فیلد کلید بلافاصله پاک می‌شود و پیام نسخهٔ ثبت‌شده را می‌بینید. خود کلید قابل Reveal از این صفحه نیست.

۶. روی کارت همان Provider، «تست آماده‌بودن» را بزنید. این تست فقط وجود کلید، رمزگشایی و Policy را بررسی می‌کند؛ مدل واقعی را فراخوانی نمی‌کند و Token/هزینه ایجاد نمی‌کند. وضعیت سالم باید «آمادهٔ استفاده» باشد.

۷. اگر می‌خواهید Provider در ارکستراسیون استفاده شود، در فرم «ثبت تغییر نسخه‌دار» ابتدا Provider را با حالت مناسب ثبت کنید، سپس Model و Agent Profile بسازید و در نهایت Profile را به Role/پروژه Bind کنید. در فیلد Credential فقط مرجع زیر را انتخاب/ثبت کنید، نه مقدار کلید:

```text
vault:hero/test/openai/default
```

برای Providerهای دیگر نام Provider عوض می‌شود.

۸. در «نقشهٔ تخصیص AI در پروژه» پروژه را انتخاب کنید و بررسی کنید هر Role، Walk-Through Guide و Smart Tester به Provider/Model/Profile موردنظر Bind شده باشد. تغییر Binding یک نسخهٔ جدید می‌سازد و کلید را جابه‌جا نمی‌کند.

## اگر خطا دیدید

- «Secret Store فعال نیست»: تنظیمات پیش‌نیاز را در Test اعمال و فقط Control Plane Test را restart کنید.
- «کلید ثبت نشده»: Provider درست را انتخاب کنید و دوباره Paste کنید؛ کلید قبلی قابل نمایش نیست.
- «نشست قدیمی است»: کد MFA جاری را وارد کنید یا یک‌بار از حساب انسانی خارج و دوباره وارد شوید.
- «آماده نیست» یا خطای Provider: متن خطای پاک‌سازی‌شده را با Smart Tester بررسی کنید. کلید را در گزارش خطا وارد نکنید.
- اگر کلید در سرویس Provider لغو/منقضی شده، در Hero «جایگزینی کلید» را بزنید و کلید جدید را ثبت کنید.

## محدودیت فعلی

ثبت کلید و تست آماده‌بودن، به‌تنهایی اجازهٔ فراخوانی زنده یا هزینه‌کردن نمی‌دهد. اجرای واقعی هنوز به مجوز مستقل هزینه، سقف Token، Policy پروژه و گیت انتشار نیاز دارد. این جداسازی عمداً از مصرف ناخواسته جلوگیری می‌کند.
