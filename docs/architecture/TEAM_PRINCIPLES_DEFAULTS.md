# اصول پیش‌فرض تیم‌ها

این سند پیش‌نویس اولیهٔ اصول ۱۱ تیم Hero است. این اصول از شروع کار به‌عنوان مقدار پیش‌فرض در `TEAM_CATALOG` قرار می‌گیرند، اما تا تأیید مالک پروژه برای بخش `principles`، تیم آمادهٔ تخصیص نیست.

مالک می‌تواند هر اصل یا مجموعهٔ اصول را از `GET /team-principles` ببیند و با `POST /api/teams/:teamId/review` با `target: "principles"` تأیید کند. برای رد یا اصلاح، `decision: "rejected"` یا `decision: "rework-requested"` همراه با feedback اقدام‌پذیر ارسال می‌شود.

## مقادیر اولیه

| تیم | اصول پیش‌فرض قابل بررسی |
| --- | --- |
| راهبرو | هدف، اولویت و معیار تحویل روشن؛ واگذاری تصمیم تخصصی به تیم مسئول؛ نسخه‌دار بودن تصمیم و دامنه؛ ارجاع ابهام و ریسک؛ ممنوعیت عملیات حساس بدون گیت |
| ایده‌پردازو | اتصال خلاقیت به مسئلهٔ کاربر؛ تفکیک ایده، فرضیه و واقعیت؛ ارائهٔ حداقل سه گزینه؛ تبدیل فرض پرریسک به آزمایش؛ توضیح ارزش، هزینه و ریسک |
| تحلیلگرو | تفکیک واقعیت، فرض، تفسیر و نظر؛ ثبت منبع و روش؛ مقایسهٔ مستقل؛ ثبت عدم قطعیت و counter-evidence؛ ارائهٔ توصیهٔ تصمیم |
| محصولو | اتصال تصمیم به outcome و کاربر؛ دامنهٔ کوچک و قابل اندازه‌گیری؛ معیار پذیرش برای هر نیازمندی؛ آشکارسازی trade-off؛ نسخه‌دار و قابل بازگشت بودن تصمیم |
| دیزاینرو | اتصال طرح به نیازمندی و معیار پذیرش؛ تقدم usability و دسترس‌پذیری؛ آزمون سناریو و خطا؛ سازگاری و نگهداری؛ ثبت دلیل تصمیم طراحی |
| معمارو | ثبت تصمیم فنی و trade-off در ADR؛ مرزهای روشن و coupling کم؛ سنجش امنیت و پایداری؛ پذیرش پیچیدگی فقط در برابر ارزش؛ آشکارسازی ریسک زودهنگام |
| دولوپرو | کد خوانا و کوچک؛ ردیابی کامل تغییر در Git؛ تحویل همراه تست و شواهد؛ نبود Secret و مسیر host در artifact؛ build قابل بازتولید در test |
| تسترو | نتیجهٔ قابل بازتولید؛ اتصال تست به معیار پذیرش و ریسک؛ نبستن ریسک مهم با حدس؛ ثبت شدت و گام بازتولید؛ استقلال تأیید کیفیت از تولید |
| امینتو | توقف برای یافتهٔ بحرانی؛ حداقل دسترسی و جداسازی محیط؛ ممنوعیت Secret در کد و لاگ؛ پیگیری شدت و اصلاح؛ امنیت به‌عنوان بخشی از طراحی و تست |
| عملیاتو | جدایی test و production و قابلیت rollback؛ استقرار نسخه‌دار و قابل مشاهده؛ گیت مستقل عملیات حساس؛ اثبات Backup/Restore واقعی؛ Runbook و مسئول رخداد مشخص |
| داده‌و | تعریف روشن سنجه و منبع؛ بررسی کیفیت و lineage؛ مصرف دادهٔ حداقلی؛ نسخه‌دار و قابل ممیزی بودن داده و مدل؛ گزارش عدم قطعیت و محدودیت |

## چرخهٔ تغییر

تحقیق تأییدشده می‌تواند پیشنهادهای جدیدی برای دانش و اصول تیم تولید کند. این پیشنهادها فقط با تصمیم `approved` مالک به `team.knowledge` و `team.principles` افزوده می‌شوند؛ گزارش ردشده یا بازکاری‌شده هیچ تغییری در تیم ایجاد نمی‌کند.
