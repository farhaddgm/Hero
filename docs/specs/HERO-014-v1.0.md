# HERO-014 v1.0 — حافظه و Context مشترک پروژه

وضعیت: مصوب

## هدف

Hero باید قواعد تأییدشده، تصمیم‌ها، معماری، evidence و artifactهای داخلی را به‌صورت حافظهٔ نسخه‌دار نگه دارد تا Agentها فقط Context مرتبط با نقش و Task خود را بگیرند؛ نه کل تاریخچهٔ پروژه.

## طراحی این نسخه

1. هر رکورد `memoryKey`، `recordVersion`، منبع داخلی `hero://`، نقش‌های مجاز و دامنهٔ Project یا Task دارد.
2. ثبت نسخهٔ جدید فقط با `supersedesMemoryId` نسخهٔ فعلی انجام می‌شود. تاریخچه append-only است و انتخاب Context فقط آخرین نسخهٔ معتبر هر کلید را می‌بیند.
3. Context برای یک Task با تطبیق دقیق `taskId + stepId + documentVersion` ساخته می‌شود. وجود حافظهٔ Task قدیمی بدون نسخهٔ منطبق، با `STALE_TASK_CONTEXT` fail-closed می‌شود.
4. Context بر اساس نقش (`planner`، `implementer`، `reviewer` یا `cursor`) فیلتر و به حداکثر تعداد رکورد محدود می‌شود؛ خروجی فقط خواندنی است.
5. secret، مسیر مطلق میزبان و مرجع خارجی رد می‌شود. این گام provider را صدا نمی‌زند، کد را تغییر نمی‌دهد و جایگزین مجوز مستقل عملیات حساس نیست.

## معیار پذیرش

- هر Agent فقط Context مرتبط و نسخهٔ صحیح را با `CONTEXT_READY` می‌گیرد.
- Context اشتباه، قدیمی یا فاقد رکورد لازم بدون حدس‌زدن مسدود می‌شود.
- تمامی بسته‌ها artifact داخلی `hero://` دارند و هیچ secret یا host path ندارند.
- Harness فقط پس از مجوز دقیق review کار می‌کند و هیچ runner واقعی ایجاد نمی‌کند.
