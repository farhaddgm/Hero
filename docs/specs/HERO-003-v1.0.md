# HERO-003 v1.0 — معماری کلان و انتخاب فناوری

وضعیت: مصوب برای توسعه و تست در 2026-08-14.

## هدف

Hero باید بتواند درخواست سادهٔ فارسی را به توسعهٔ سریع، قابل‌کنترل و قابل‌تحویل اپلیکیشن وب یا موبایل تبدیل کند؛ بدون آن‌که در شروع به مجموعه‌ای سنگین از سرویس‌های جداگانه تبدیل شود.

## تصمیم معماری

سبک انتخاب‌شده `modular-monolith-with-isolated-runners` است: یک Control Plane یکپارچه و ماژولار برای تصمیم‌گیری و هماهنگی، همراه با Runnerهای ایزوله برای کارهایی که کد، Git، ابزار AI یا commandهای پروژه را اجرا می‌کنند.

این انتخاب سرعت توسعه و دیباگ را بالا نگه می‌دارد، ولی از همین ابتدا مرزهای قابل‌استخراج برای Provider، Storage، Runner و رابط کاربر را حفظ می‌کند. تبدیل به microservice فقط پس از شواهد عملی مانند بار مستقل، نیاز امنیتی مستقل یا نرخ استقرار متفاوت انجام می‌شود.

## لایه‌ها و مرزها

1. Experience: Console فارسی ساده با چهار تجربهٔ خانه، جزئیات کار، مرکز تصمیم و تحویل.
2. Application: Use caseهای دریافت درخواست، برنامه‌ریزی، بررسی مجوز، Dispatch، تحویل و بازیابی.
3. Domain: قواعد قطعی State Machine، مجوز نسخه‌دار، کنترل تغییر و Definition of Done.
4. Ports: قراردادهای Storage، Provider، Runner، Git و Notification.
5. Adapters: پیاده‌سازی قابل‌تعویض Portها؛ هیچ Adapter نباید منطق Domain را در خود نگه دارد.
6. Execution: Runner ایزوله با worktree/container، checkpoint امن، نتیجهٔ تست و Evidence.

Console حق اجرای command یا نگه‌داری Secret ندارد. Control Plane فقط پس از تأیید مجوز مؤثر، اجرای یک Run را به Runner می‌سپارد. هر Run یک مسیر کاری مستقل و یک مسیر Evidence دارد.

## مسیر استاندارد

درخواست فارسی → فهم و سؤال‌های ضروری → Task Graph و معیار پذیرش → بررسی مجوز نسخه‌دار → Dispatch ایزوله → توسعه و تست → بازبینی مستقل → تحویل قابل فهم

هر بخش که داده یا Adapter معتبر نداشته باشد fail-closed متوقف می‌شود. عملیات حساس (Production، هزینه بیرونی، Secret، حذف داده، پیام بیرونی و عملیات برگشت‌ناپذیر) از این مسیر عمومی جدا و همچنان نیازمند تأیید مستقل‌اند.

## انتخاب فناوری

| بخش | انتخاب | علت |
| --- | --- | --- |
| Control Plane | Node.js 22، ESM؛ مسیر هدف TypeScript | سازگاری با پایهٔ فعلی و سرعت توسعه، همراه با امکان قراردادهای type-safe |
| Console | React + Next.js + TypeScript | تجربهٔ وب ساده، سریع و قابل‌استفاده برای مالک غیرتوسعه‌دهنده |
| دادهٔ عملیاتی | PostgreSQL در HERO-005 | تراکنش، Event Log append-only، Snapshot مجوز و Outbox قابل‌اعتماد |
| Dispatch | Outbox و صف پایدار مبتنی بر PostgreSQL | حذف زیرساخت اضافه تا وقتی نیاز واقعی اثبات نشده باشد |
| Runtime مرجع | Linux container + Docker Compose | انتقال‌پذیری و جداسازی از میزبان |
| خروجی وب | TypeScript + Next.js/React | الگوی پیش‌فرض کارخانهٔ توسعهٔ وب |
| خروجی موبایل | TypeScript + Expo/React Native | توسعه و preview سریع موبایل بدون وابستگی اولیه به iOS محلی |

در این گام هیچ Provider، دیتابیس یا صف خارجی متصل نمی‌شود و هیچ Secretی ثبت یا تغییر نمی‌کند.

## نقش سه ابزار اولیه

## ساختار هدف مخزن

```text
apps/
  console/                 رابط سادهٔ فارسی
  control-plane/           API و هماهنگی Use caseها
workers/
  execution-runner/        اجرای ایزولهٔ Runها
packages/
  domain/                  قواعد قطعی
  application/             Use caseها
  contracts/               قراردادهای بدون وابستگی
  adapters/                Provider، Storage، Git و Runner
```

ایجاد فیزیکی هر بخش فقط در گام مربوط به خود انجام می‌شود؛ این سند مرزها را تعریف می‌کند، نه این‌که dependency یا زیرساخت زودهنگام اضافه کند.

## معیار پذیرش

1. معماری یک Control Plane ماژولار و Runner ایزوله را با مرز وابستگی روشن تعریف کند.
2. نقش Codex/ChatGPT، Claude و Cursor جدا و بدون اتصال واقعی مشخص باشد.
3. مسیر فناوری برای Console، داده، Queue، Container و کارخانهٔ وب/موبایل روشن باشد.
4. انتخاب‌ها با Clean-room، انتقال‌پذیری، fail-closed و گیت عملیات حساس سازگار باشند.
5. قرارداد ماشینی، ADR، آزمون‌های خودکار و `pnpm check` موفق باشند.
