# HERO-011 v1.0 — اتصال Codex و ChatGPT

وضعیت: مصوب برای توسعه و تست در 2026-08-14.

## هدف

Hero باید بتواند یک درخواست محصول را ابتدا به یک تحلیل ساختاریافته بسپارد و سپس Task حاصل را به اجراکنندهٔ Codex بدهد. خروجی هر اجرا باید به‌صورت دادهٔ ساختاریافته شامل فایل‌ها، تست‌ها، خطاها و Artifact ثبت شود.

## طراحی این نسخه

1. `chatgpt` و `codex` پشت قرارداد Adapter مستقل قرار می‌گیرند؛ در نتیجه CLI، API و شبیه‌ساز قطعی همگی بعداً قابل جایگزینی‌اند.
2. Adapter پیش‌فرض قطعی است: هیچ شبکه، CLI، credential، هزینه یا تغییر repository انجام نمی‌دهد؛ این حالت مسیر کامل تحلیل تا گزارش را قابل تست می‌کند.
3. Adapter غیرفعال fail-closed است و با `PROVIDER_DISABLED` متوقف می‌شود. اتصال واقعی Provider، احراز هویت، هزینه، merge، deploy و تغییر secret خارج از دامنهٔ این گام‌اند.
4. Harness نمونه پیش از Provider Pipeline، مجوز نسخه‌دار را ارزیابی، Worktree ایزوله را آماده، Runner را شروع و پس از ثبت شواهد در checkpoint امن پاک‌سازی می‌کند.

## قرارداد نتیجه

نتیجهٔ Codex باید چهار کلید ثابت `files`، `tests`، `errors` و `artifact` داشته باشد. نتیجهٔ قطعی صراحتاً می‌گوید که تغییر واقعی repository رخ نداده است تا شبیه‌سازی با اجرای واقعی اشتباه گرفته نشود.

## معیار پذیرش

1. تحلیل ChatGPT و اجرای Codex در Pipeline جدا اما به‌هم‌پیوسته و idempotent اجرا شوند.
2. خروجی تکمیل‌شده شامل فایل‌ها، تست‌ها، خطاها و Artifact باشد.
3. ورود شبیه secret رد شود و Provider غیرفعال، بدون اجرای ناخواسته، fail-closed شود.
4. اجرای Harness فقط با مجوز معتبر، Worktree ایزوله و checkpoint/cleanup امن تکمیل شود.
