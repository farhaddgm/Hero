# HERO-016 v1.0 — حلقه تست، بازبینی و اصلاح

وضعیت: مصوب

## هدف

Hero باید هر ادعای موفقیت را به شواهد ساختاریافتهٔ تست متصل کند و پس از بازبینی مستقل، فقط با مجوز نسخه‌دار جداگانه وارد اصلاح و بازآزمایی شود. این چرخه نباید بی‌نهایت یا بی‌سقف هزینه ادامه پیدا کند.

## طراحی این نسخه

1. Quality Gate با Step ID، نسخه سند، Run و Task مشخص باز می‌شود و پیش از پذیرش شواهد، مجوز دقیق `test` و خاموش‌بودن توقف سراسری را می‌سنجد.
2. شواهد تست باید اجرای کامل Codex، تست‌های صریحاً موفق، Worktree ایزوله و Artifact داخلی را اثبات کنند. شواهد نامعتبر یا ناامن با توقف امن رد می‌شوند.
3. بازبینی از مسیر مستقل Claude انجام می‌شود. در این نسخه مسیر deterministic است: هیچ CLI، شبکه، credential، فراخوانی واقعی مدل یا تغییر Repository رخ نمی‌دهد.
4. اگر بازبینی اصلاح بخواهد، Gate فقط وضعیت `fix-required` ثبت می‌کند. آغاز اصلاح نیازمند مجوز دقیق `develop` و Task اصلاح جداگانه است؛ خود Review هرگز کد را تغییر نمی‌دهد.
5. پس از اصلاح، بازآزمایی و بازبینی از همان Gate انجام می‌شود. `maxCorrectionCycles` و `maxCostUnits` پیش از عبور از سقف بررسی می‌شوند. نتیجه نهایی فقط `approved` یا `stopped` است.

## معیار پذیرش

- تست موفق، بازبینی تأییدشده و نتیجه `QUALITY_APPROVED` به شکل append-only ثبت شوند.
- بازبینی دارای یافته، بدون تغییر پنهان کد، به `FIX_REQUIRED` و سپس Task اصلاحِ مجاز تبدیل شود.
- عبور از سقف چرخه یا سقف هزینه، و نیز توقف سراسری، Dispatch تازه را متوقف و دلیل را ثبت کند.
- هیچ اتصال واقعی به Codex/ChatGPT، Claude یا Cursor، هیچ هزینه واقعی، merge، deploy یا عملیات حساس در این گام انجام نشود.
