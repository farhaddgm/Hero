# HERO-012 v1.0 — اتصال Claude

وضعیت: مصوب برای توسعه و تست در 2026-08-14.

## هدف

Hero باید بتواند evidence ساختاریافتهٔ اجرای Codex را به یک بازبین مستقل Claude بدهد و نتیجه را به‌صورت «تأیید» یا «نیازمند اصلاح» همراه با یافته‌های قابل پیگیری ثبت کند.

## طراحی این نسخه

1. Claude در نقش Reviewer مستقل قرار می‌گیرد؛ قرارداد آن از Pipeline تحلیل و اجرای ChatGPT/Codex جداست.
2. چهار دستهٔ ثابت یافته شامل `architecture`، `security`، `edge-case` و `tests` است. هر یافته شناسه، شدت، مرجع، مسئله و اقدام پیشنهادی دارد.
3. Adapter پیش‌فرض قطعی است. هیچ Claude CLI یا API، شبکه، credential، هزینه یا تغییر واقعی repository انجام نمی‌شود.
4. Adapter غیرفعال fail-closed است و با `CLAUDE_REVIEW_DISABLED` متوقف می‌شود.
5. Harness نمونه، مجوز نسخه‌دار با operation=`review` را ارزیابی می‌کند، اما Worktree نمی‌سازد؛ بازبینی evidence فقط خواندنی است.

## مرز اصلاح

نتیجهٔ `changes-requested` فقط شواهد بازبینی است، نه مجوز تغییر. Claude هرگز فایل یا repository را اصلاح نمی‌کند. هر اصلاح حاصل از یافته‌ها باید در یک Task جداگانه، با سند نسخه‌دار و مجوز مستقل شروع شود.

## معیار پذیرش

1. بازبینی clean evidence صراحتاً تأیید می‌شود و replay idempotent دارد.
2. evidence ناقص یا ناامن، یافته‌های ساختاریافتهٔ معماری، امنیت، edge case و تست تولید می‌کند.
3. ورودی شبیه secret پیش از بازبینی رد می‌شود و Claude غیرفعال بدون Artifact fail-closed می‌ماند.
4. Harness فقط با مجوز دقیق `review` برای Step ID و نسخهٔ سند یکسان اجرا می‌شود و هیچ Worktree یا تغییر repository ایجاد نمی‌کند.
