# منشور پروژه Hero

- نسخه: 1.0
- وضعیت: مصوب
- گام: HERO-001
- تاریخ اثر: 2026-08-14
- صاحب تصمیم نهایی محصول: مالک پروژه

## Hero چیست؟

Hero یک سیستم توسعه نرم‌افزار مبتنی بر AI است که باید درخواست ساده‌ی فارسی مالک را به تحلیل عمیق، طراحی روشن، پیاده‌سازی، تست، بازبینی و خروجی قابل تحویل برای اپلیکیشن وب یا موبایل تبدیل کند.

مالک پروژه توسعه‌دهنده نیست؛ بنابراین رابط و گزارش Hero باید ابتدا نتیجه، وضعیت و تصمیم لازم را با زبان ساده توضیح دهد. جزئیات فنی در لایه‌ی بعدی قرار می‌گیرند.

## هدف محصول

Hero باید سرعت توسعه را بالا ببرد، بدون اینکه کنترل، کیفیت، امنیت یا قابلیت انتقال قربانی شود. نسخه‌ی نخست فقط از سه مجموعه ابزار استفاده می‌کند:

1. ChatGPT و Codex برای تحلیل، معماری و اجرای توسعه
2. Claude برای بازبینی مستقل و یافتن خطا
3. Cursor برای Cockpit انسانی و تحویل Context، Diff و دستور اجرا

هسته باید بدون Cursor و به‌صورت Headless هم کار کند. هیچ Provider نباید مستقیماً در منطق اصلی قفل شود؛ همه‌ی اتصال‌ها پشت Adapter قرار می‌گیرند.

## دامنه‌ی محصول

دامنه‌ی نسخه‌ی برنامه شامل تحلیل محصول، طراحی، ساخت وب و موبایل، تست خودکار، بازبینی مستقل، مستندسازی، نسخه‌گذاری و تحویل قابل تکرار است.

موارد زیر حتی با اختیار کامل توسعه، گیت مستقل دارند:

- انتشار Production
- خرید یا هزینه‌کرد خارجی
- تغییر یا نمایش Secret
- حذف یا overwrite دائمی داده
- ارسال پیام یا اقدام خارجی به نام مالک
- هر عملیات برگشت‌ناپذیر

## اصول غیرقابل مذاکره

- Hero یک مخزن Clean-room مستقل است.
- کد، فایل، دیتابیس و سرویس پروژه‌های دیگر قابل استفاده نیست.
- Runtime مرجع Linux container است.
- هر ادعای تکمیل باید Evidence داشته باشد.
- تصمیم‌ها، مجوزها و Runها append-only و قابل حسابرسی‌اند.
- وضعیت ناشناخته یا خطای نسخه یعنی توقف.
- تغییر قاعده‌ی مصوب به نسخه و Change Log جدید نیاز دارد.

## صاحب تصمیم و مسئولیت‌ها

مالک پروژه هدف محصول و عملیات حساس را تعیین می‌کند. Orchestrator در محدوده‌ی مجاز، طراحی و پیاده‌سازی را پیش می‌برد. کیفیت نهایی با تست‌های قطعی و بازبینی مستقل کنترل می‌شود؛ نویسنده به‌تنهایی تأییدکننده‌ی خروجی خود نیست.

## مدل اختیار

حالت پیش‌فرض، تأیید گام‌به‌گام است. اختیار کامل فقط با Snapshot نسخه‌دار و فهرست دقیق Step ID و نسخه سند ایجاد می‌شود. Snapshot جاری با شناسه BATCH-ROADMAP-20260814-001 تمام ۲۱ گام فعلی را برای طراحی، مستندسازی، نسخه‌گذاری، توسعه، تست، بازبینی و commit پوشش می‌دهد و با دستور مالک قابل لغو است.

## تعریف تکمیل

یک گام فقط وقتی Done است که معیار پذیرش آن برآورده، تست‌ها موفق، کنترل Clean-room موفق، مستندات به‌روز، شواهد ثبت و مانع امنیتی مهم نداشته باشد. مسیر بازگشت یا بازیابی نیز باید شناخته‌شده باشد.

## روش تغییر منشور

این منشور درجا و بی‌ردپا تغییر نمی‌کند. تغییر معنادار باید نسخه‌ی جدید، دلیل، Change Log و در صورت اثر معماری ADR داشته باشد. نسخه‌های قبلی حفظ می‌شوند.
